Policies.
Which apps and updates your hosts should have — kept that way in a maintenance window
How policies work
  1. Pick hosts. A policy covers every managed host with one of its tags (or every managed host if you leave tags blank).
  2. Say what they should have. On Apps, each rule keeps one app Present, Latest, Pinned to a version, or Absent. On Patching, choose which OS updates install, how long to wait after one appears, and when hosts may restart.
  3. Vigil compares. Each host's software inventory is checked against the rules. Preview shows which hosts would change and how — compliant hosts are never touched.
  4. It fixes drift in the window. When the maintenance window opens, Vigil runs one generated task on the drifted hosts only (in waves if you set a wave ladder). With Approve each change on, the changes wait below for you to approve instead.

The generated task is an ordinary task — open it from Preview to see exactly what runs. Approving or declining an update on Apps → By update applies to every policy.
